# Published native resource owners and concrete template recipes

Source 2.159 / System 2.85 publishes automatic native `@resource` owners with
exact callback, invalid-sentinel and value/address invocation identity. Callback
and sentinel dependencies must be exported; canonical bodies retain qualified
callback names and explicit function-template arguments. Resource body changes
participate in interface fingerprints and source-free reader admission.

Dependent handle types, close callbacks and invalid sentinels retain declarative
recipes until template instantiation. Deduced `auto` handles are rebound after
their initializer determines the type. Every concrete recipe passes the native
mutable scalar handle, synchronous unary callback, argument-conversion and
constant sentinel checks before ownership/CFG analysis or code generation.
Unresolved recipes cannot reach a concrete executable body. Fields, static
storage, reference/const/non-scalar handles and invalid callbacks remain rejected.

Explicit function-template close callbacks now resolve consistently in resource
typedef contracts, local resource owners and automatic cleanup. The selected
specialization retains its explicit arguments and reverse resource association.
`objc3.native-storage-lifetime.v4` requires rebuilding interfaces; native runtime,
frame and service ABI layouts are unchanged.

Permanent controls cover dependent/deduced handles, type-directed callback and
sentinel selection, explicit specializations, value/address invocation and invalid
storage/signature/sentinel diagnostics through source/PCH replay. Publication
controls check exact replay, relocation, callback/sentinel fingerprints, hidden
callback rejection and consumer instantiation. Source-free native consumers check
normal/invalid handles, reset/take/discard, throwing close, failed initialization
and ordinary exceptional scope exit. Full rebuilt compiler/SDK acceptance remains
pending.
