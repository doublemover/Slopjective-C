# C++ factory result types in template arguments on Linux

Source **2.81** admits checked template type arguments whose local or anonymous
tags belong to complete module-owned concrete factories. Canonical argument keys
retain ordered nominal origins through nested specializations, packs, pointers,
arrays and member-pointer types. Unqualified local tags and mixed packs containing
an unmodeled local type remain rejected.

Runtime dependency discovery binds factory arguments in explicit and deduced
calls, closed generic lambda instances and specialization tables. Complete
published owners carry `objc3.cxx-factory-template-arguments.v1`; missing capabilities
and namespace-only owners fail with `O3IFC090`. Factory visibility and dependency
checks continue to apply through aliases and nested argument types.

Implementation witnesses cover primary and full/partial class selection, alias
and variable templates, provider-owned function/storage specializations, nested
wrappers, packs and nontrivial owned values. The [focused source receipt](../support/linux_cxx_factory_template_arguments_progress.json)
records all 43 native import-family tests, the emitter suite, 84 tooling tests
and the full 16-case focused factory matrix / 96 commands passing;
broader fixture/sanitizer checks and SDK delivery remain batched. Factory-valued
non-type arguments, generic/closure factory origins, broader unnamed-type and
language/profile contracts remain open. SDK 2.62 stays accepted, and native Linux
AArch64 remains unqualified.
