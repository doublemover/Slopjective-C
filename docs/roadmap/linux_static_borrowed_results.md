# Borrowed results backed by immutable program storage

Current execution checkpoint: the maintained native frontend replay, identity and
consumer controls pass in the ABI 24 development embedding. See the
[2.110 consolidation](linux_publication_and_byte_ranges.md). Source-free package
execution, wider matrices and installed SDK qualification remain pending.

System source 2.20 accepts owner-contracted borrowed results whose addresses are
proven to refer to immutable program storage. The native constant evaluator
resolves readonly arrays, external readonly storage, stable record subobjects,
immutable aliases, C file-scope const compound literals and constexpr calls.
Bounded composition preserves static provenance through pointer offsets, casts,
conditionals, null alternatives and comma expressions. Ordinary pointer bounds
and access rules continue to apply.

The proof excludes TLS, automatic storage, mutable bases, unknown pointees,
mutable fields, unions, cleanup-managed storage and nontrivial destruction.
A constant pointer slot is not proof that its pointee has static lifetime: the
complete rvalue load must resolve the actual base. Constant evaluation must have
no side effects or undefined behavior. Existing live/expired loan facts are
never erased, and callers retain the public nonescaping owner contract even when
a provider implementation returns static bytes. This extends return precision;
it does not infer arbitrary global mutation or runtime interprocedural effects.

The proof runs only during the final diagnostic pass, avoiding repeated constant
evaluation in the CFG fixed point. The new regression passes eighteen
C17/C++20/C++23 ARC/MRC source/PCH commands. All twenty borrowed compiler
regressions pass alongside native dependent-await source/PCH and printing
controls: twenty-two tests in the combined focused selection. Frontend
replay/relocation, changed-body and valid/escaping consumer controls are authored;
frontend execution and final SDK consolidation remain pending.

The accompanying dependent-await correction uses the complete native opaque
suspension protocol as its marker. Ordinary dependent C++ `co_await` keeps its
spelling and coroutine semantics, and does not require native dependent-await
publication support. Both source and PCH printing controls pass. No public
layout or extension ABI change is introduced; SDK 2.62 is unchanged.
